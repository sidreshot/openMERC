# Intentional deviations from the original

OpenMerc reproduces the original's observable behaviour unless there is a security, privacy or platform
reason not to. Every deliberate difference is listed here with its reason and how to restore the original
behaviour where that makes sense.

| Area | Original (spec) | OpenMerc | Reason | Switch |
|---|---|---|---|---|
| Fixed tables (network, Ghoul, demos) | the engine uses the original's 250-entry direction table, a 1927-string configstring dictionary, a 3713-string Ghoul string dictionary and its Huffman weights (SPEC-201 App. A/C/D, SPEC-203 App. A); SPEC-145 would extract them from SoF.exe | directions are generated (frequency-5 geodesic icosahedron, same order, within 1e-6 of the original, not bit-identical); no dictionaries, every string is sent as text; own Huffman weights; SoF.exe is never read (SPEC-145 SUPERSEDED by user decision 2026-10-26) | owner decision 2026-10-26: no data copied from the original in the open tree | none: **no network or demo compatibility with original 1.07f servers, clients and demos**; OpenMerc to OpenMerc and the original game modules (mode A) are unaffected |
| GameSpy quit heartbeat | every process sends a heartbeat to the master when it quits, even private ones (SPEC-204) | only public servers send it | players should not announce their address to third-party masters | — |
| GameSpy masters | one GameSpy master (dead) | queries and announces to several community masters (default: sof1master.sofvault.org, master.333networks.com, master.openspy.net), merged and de-duplicated (the original queries every duplicate record of a list, SPEC-AMEND-005 GS.11: same servers listed, fewer `\status\` queries, the shown ping may come from another duplicate) | the original master is gone | `cl_masters`, `sv_masters` |
| GameSpy lobby chat server | `gsc_server` default `peerchat.gamespy.com` (SPEC-204 §5; the host no longer exists) | default `peerchat.openspy.net` (OpenSpy's Peerchat, an IRC-compatible server on port 6667, https://github.com/openspy/openspy-core; verified 2026-10-22/25 with the original and OpenMerc clients); a stored `peerchat.gamespy.com` (e.g. from an original `config.cfg`) is replaced at start | the original chat host is gone | `gsc_server`, `gsc_port` (set after start to use any host) |
| GameSpy lobby chat connect | the TCP connect blocks the frame (SPEC-204 §5) | non-blocking connect, given up after 30 s with the original's failure message | a dead chat host would freeze the game | — |
| `gsc_nick` after a NICK change | set to the new nick of **any** user who changes nick in view (SPEC-204 §5.5, seen black-box) | set only when the own nick changes | the original renames the player after a stranger (and saves it in `config.cfg`) | — |
| Query responder | no rate limit (SPEC-204) | per-address rate limit (planned) | the original can be abused for UDP traffic amplification | cvar to be defined |
| Upper-case key names in configs | — | accepted | SoF configs bind `W`, `A`, `S`, `D` in upper case | — |

| Developer Mode warning | message box at start when `developer` is non-zero (SPEC-301 B1 step 7) | console line instead | a modal box blocks unattended and scripted starts | — |

| Glass seal clips (collision map load) | the map's brushes are used as compiled: tsr1 has non-solid PLAYERCLIP / trigger-WINDOW brushes inside breakable panes, which keep blocking after the glass breaks ("ghost stand" at the TV booth) | at map load a world non-solid PLAYERCLIP brush, or a trigger-textured WINDOW brush, is ignored only when at least half of its volume lies inside a `func_breakable` pane and there is open floor 24 units out on both sides of the pane. | Unknown console words in single player | both game modules turn a word they do not know (e.g. `notarget`, which the original does not have) into `say <word>`: a chat line to nobody | single player only (one slot, not dedicated): if a command other than `say`/`say_team` ends up as chat, nothing is sent and the console prints Quake II's `Unknown command "<word>"`. Multiplayer is unchanged | the chat line was useless and, with the old high-bit chat colouring, drew as garbage | — |
| Keyboard text (console, chat line) | a key types the character of SoF's own layout table (US, or the German/French/Spanish table of `sp_language`); other layouts (Russian) type the US character of the key | the operating system's character for the same key press replaces the table's character (Windows `WM_CHAR`, SDL text input elsewhere), converted to the font's byte: Cyrillic -> CP1251, U+00A0-U+00FF -> Latin-1, anything else dropped; Yo/yo become Ye/ye (no glyph in the SoF fonts). With a German/French/Spanish table only non-ASCII characters replace the table's. Bindings, the console key and line lengths are unchanged (the OS text never adds a key press); a Windows `VK_PACKET` press (input methods, on-screen keyboard) inserts its characters; a UTF-8 clipboard pastes as font bytes | Russian players could not type Russian in the console or chat | — |
| Console and chat text bytes 128-255 | Quake II draws chat and the version line with the "alternate" high-bit charset (byte \| 128) and treats bytes 128-255 as whitespace when parsing commands (signed `char`) | SoF fonts have no alternate charset: bytes 128-255 are Latin-1 / CP1251 letters (the Russian `conchars`), so text is drawn as is, chat is not OR-ed with 128, and the command parser, `COM_Parse` and the console word wrap read bytes as unsigned (`say` with Cyrillic text now reaches the game) | with the Russian font chat and `notarget` rendered as random Cyrillic | — |
| Running-effect pool (client FX) | at most 256 running effects; a start that finds all slots in use is ignored (SPEC-201, SPEC-400); entity effect slots re-start every rand(repeat delay) even while the previous instance of the same slot still runs | (1) a start attached to the local player's own entity (view-weapon notes, own muzzle) never fails for a full pool: the farthest non-own running effect is freed and the slot reused; a world start replaces that farthest effect only when it is at least 1024 units nearer, otherwise it is dropped; (2) by default an entity effect slot starts its next instance only once the previous one of that slot has stopped emitting and fired every primitive (`om_fxslotstack 0`), so long looping effects with a short repeat delay (e.g. `environ/onfireburst`, repeat 0.05 s, emitters live 6-13 s) do not pile hundreds of copies into the pool | tsr1: four burning entities ~3000 units away restarted `onfireburst` ~22 times/s and kept the pool full (~4800 starts dropped in 96 s), so the first-person muzzle flash never started and own fire sound was silent; the fov==95 path was already correct | `om_fxslotstack 1` = the 1.07f re-start rule; pool admission has no switch |

## Savegames survive rebuilds (2026-11-08)

- **Pointers saved by name** (game/src/save/save_symtab.cpp, tools/om_symtab.py): callbacks and static tables are
  saved as the names of their symbols (OMSY chunk after FTSZ; "name+hex" inside a table), resolved by the reading
  build's symbol table, which the build writes into the module from the linker map (MSVC /MAP, LLD -Map; Python 3
  needed). FTSZ is 'OMG2' and checks only the record layouts (entity, client, level, entity image, extension count):
  a rebuild with other code reads the save, a change of edict_t / gclient_t / level_locals_t still refuses it. Saves
  of the former format ('OMG1', offsets of one build) are refused. The original module's saves never loaded.
