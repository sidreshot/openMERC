### Parental locks (registry, reported)
Every local/loopback game of the original executable on this PC is refused (`rejected_violence`): the lock words
in `HKCU\Software\Raven Software\SoF` were written for another volume serial, so the engine treats them as
invalid and forces all locks (cl_violence 63 > sv_violence 31). `run_session.ps1` therefore verifies the key
against the backup `openmerc-data\i7\sof-registry-backup.json`, writes valid "off" words for this PC
(`sof_locks.py unlock`, SPEC-313 Appendix A), starts the game(s), and restores the key byte-identically as soon
as the game has read it (and again in `finally`); every run prints `restored, identical: True`.
Appendix A detail confirmed: 15 words are drawn (pairs for values 0-5, K, pair for value 6), not 14; the stored
foreign values are the "off" words of pairs 1-5 of another key, password empty.

## Black-box facts (original 1.07f module, not in the specs or differing from them)

Player state offsets written by the module (owner `edict+0x74` → client record, player state at 0):
`0x6C` view-weapon instance pointer, `0x72` uint16 weapon id of the view weapon (the engine writes the handle at
`0x70`), `0x74` int16 clip, `0x76` int16 reserve, `0x78` byte weapon-state sequence (`0x79` = resync, game),
`0x94` float fov. The weapon kick is written through the owner-context pointer; the game copies it to `0x40`.
- Every new view instance gets the transform rows (0 1 0), (-1 0 0), (0 0 1): a 90° turn about Z (the stock
  models face −Y). The player module applies it, not the renderer.
- Boolean inventory results: the game tests the whole EAX (our `bool` returns broke `heretic`/`elbow`); all
  boolean slots return a full int.
- Slot 64 ORs the persistence weapons into the caller's mask (the game pre-fills it with the map's weapons).
- New inventory defaults: B = −1 (SPEC-601 says 0); target slot 0; animated weapon 1; seq name "unused
  viewmodel"; stance flag 0x208 = 1; prepaid 1. The original leaves 0x190 (owner context) and 0x270 (idle
  counter) uninitialised and fills the tag's padding with garbage on the client (explained differences).
- Event block: count byte and `(class<<4)|id` headers; −1 is sent as class 3, 0 as class 0.
- The module passes the owner context pointer as the first ("unused") argument of fire imports 2/3.
- Sniper: the idle variation needs word 0x208 (set by draw and reload); before that the plain idle is chosen
  without touching the variation counter. The saved zoom becomes 60 when `scopein` ends.
- Shotgun shell loading: each `reload_loop` end loads one shell and sets ready (fire can interrupt); the loop
  that finds the clip full (or no shells) is followed by `reload_2`, i.e. N shells take N+1 loops (SPEC-600 test
  vector 4 says N).
- A frame whose weapon request did something still runs the items think (goggles timing); no attack starts.
- Refire: the note at 0 ms of a refired sequence is delivered on the next think (pistol: first shot at once,
  then 0.4 s, then every 0.3 s).
- Item messages: `PrintId(owner, 0x30E, newCount, displayName)`, also after `itemdrop`.
- Goggles: battery/time steps happen when `now > next` (strict), giving a 0.6 s period at 10 Hz.
- Shotgun/pistol stances etc. as in SPEC-600; slot 8 calls slot 7 through the method table.
- Automatic shots (assault, machine pistol, machinegun, rocket alternate): the shot time (0x27C) is recorded
  before the round is paid, and a note that finds the clip empty starts the automatic reload at once (SPEC-600
  test vector 8). Single rockets and the machinegun grenade record the shot time too.
- A refire that cannot be paid (e.g. MPG burst with 5 of 10 units) starts the automatic reload (rounds moved,
  import 4 called) and then goes idle, which replaces the reload animation.
- Machinegun: releasing the button goes idle at once with the spread kept (as assault / machine pistol);
  `fire1_2` is not reached. Flamethrower release: idle choice (looping sound reset, variation counter used),
  then `fire1_2` and another sound reset; the reset clears the loop data byte too.
- Hand pseudo-weapon end: slot 11 resolves the best weapon into a slot request (code 8 + slot), ready becomes −1
  (state stays 5) and the request is processed on the next think although ready is −1; the new weapon is drawn
  at once. `itemdrop` of a whole slot (goggles) prints no message.
- Idle-variation counter 0x270: not initialised by the constructor, decremented once when non-zero. Values seen:
  0 (fresh memory: single-player server inventories), the previous inventory's value - 1 (reused block, e.g. 1
  after an inventory that ended at 2), heap text (client and dedicated-server inventories: 0x57455448,
  0x52415F51, 0x434F524F, ...), one less for every inventory created in the process. OpenMerc: 0 on a listen
  server, 0x40000000 on the client and on a dedicated server (no client API loaded).
- Predicting owner (server): pending fire times are read every think through imports 13/15 (verbose trace) and
  cleared through 14/16 after use, when a reload is attempted, and when the new weapon is drawn at the end of a
  switch.
- Predicted switch (server): the new instance is created and its idle chosen (one idle choice) before the
  put-away starts on the old instance; the player state gets the new instance, weapon id, clip and reserve in the
  same think; at the end of the put-away the draw starts without another idle choice, with the draw stance.
- Client follower: dictation = the request plus an idle choice (counter used) and the predictor's own put-away;
  adoption of the server's instance = idle choice, then the draw with its stance (pistol1 a, sniper "drawn").
- Original predictor and server can disagree on the pistol1 stance (server `fire1_b`, client `fire1_a`): after
  `elbow` the server selects the 9 mm without a draw (stance b of a new inventory), the predictor draws `ready_a`.
- Machine pistol: the attack start leaves the pre-paid flag (0x264) alone; the first note is free while it is
  set (new inventory: 1; set again by refires) and takes a second round when it is 0.
- Slugger: `ready_idle` (first idle after the draw) sets the variation counter to 2.
- The fire-time getters (13/15) are side-effect free and asked only while the weapon is ready (both modes, also
  without an alternate attack; none while a sequence plays). The pending time of the refired mode is cleared at
  every refire, also when the button decides it (flamethrower, MPG, knife primaries). The clears (14/16) are
  compared and match.
- Export 11 (rebuild after a full restore) registers a new model object for the current weapon (RegisterGsq, no
  sound/effect/attack precache) instead of using the cached one; the view-weapon id then reaches the player state
  one frame later than with the cached object.
