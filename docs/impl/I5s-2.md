## Design (0.2; 0.3 = 0.2 + the fixes of 2026-10-25; 0.4 = SPEC-AMEND-006)
OMsnd 0.1 played every sound on its own OpenAL source (OpenAL's distance model, OpenAL mixing, EFX reverb on
positional sounds). SPEC-040 describes Defsnd as the Quake II 3.19 mixer with SoF additions, with exact integer
volume formulas, block-wise mixing and sample-time fades, so 0.2 *is* that mixer:

| File | Origin | Content |
|---|---|---|
| `snd_dma.c` | Quake II 3.19 `client/snd_dma.c` (GPL, id header kept) | exports, registration, channels, spatialization (+ near radius N), S_Update order of SPEC-040 1.5, commands |
| `snd_mix.c` | Quake II 3.19 `client/snd_mix.c` | paint loop, 8/16-bit paths (+ gain g on 16-bit only), `.adp` path, music first |
| `snd_mem.c` | Quake II 3.19 `client/snd_mem.c` | WAV loader/resampler (exact Quake II rules), `.adp` loading (length 2·size − 46) |
| `snd_adp.c` | OpenMerc | SPEC-110 decoder, SPEC-040 1.3 ratio rule |
| `snd_ambient.c` | OpenMerc | SPEC-040 2–4: general sets + crossfade, random one-shots, point sets, entity loops |
| `snd_music.c` | OpenMerc | SPEC-040 5: five tracks, fades in output samples, state machine, forcesong |
| `snd_out.c` | OpenMerc | the mixed 16-bit stereo stream at rate R → one OpenAL Soft streaming source (direct channels, gain 1, no limiter); DMA clock emulation; `s_om_wavefile` digital capture |
| `snd_efx.c` | OpenMerc (0.1) | EAX-style reverb, now an option (`s_om_reverb 1`, default 0; Defsnd has none) on the whole output |
| `snd_engine.c` | OpenMerc (0.1) | engine imports by name (+ irand, FS_FOpenFile/FCloseFile), sound-struct accessors |

EAXSnd and A3Dsnd (SPEC-040 6, 7) are not reproduced; OMsnd always behaves as Defsnd. Options for later, if a
player wants the other backends' sound (each would be a cvar, default off = Defsnd):
- EAXSnd: DirectSound3D-style distance model (minimum distance 262.47 units, gain = min/(min + rolloff·(d − min)),
  local sounds 26.25 units in front), no channel override per entity/channel, 32 instances per sound, one-shots never
  loop (cue chunks ignored), music `flag` = loop for every piece (stock Tension/Action play once), frame-based music
  fades (0.005 per frame), general ambience switches without crossfade (first one-shot at once, ≥ instead of >), point
  loops at full volume at the source, entity loops at fixed volume 0.6, no `*` sounds, no `forcesong`/`play`/
  `soundlist`, reverb from `.eal`/map presets (`s_om_reverb 1` already gives an EAX-style reverb on the whole mix),
  underwater = reverb preset 22 instead of the 0.3 gain.
- A3Dsnd without A3D hardware is Defsnd except: listener sounds forced to volume 255, loop sounds sharing data divided
  by the number of channels playing it, music mode 2 from a non-designer state other than 3 does nothing, negative
  entity numbers for general ambient loops. With A3D hardware: 16 hardware voices with geometry occlusion/reflections
  (needs SPEC-040 open question 1).

OpenMerc cvars: `s_om_debug` (bit 1 events: music modes/fades/pieces, ambient set changes, proc type; bit 2 ambient
one-shots and entities; bit 4 sound starts — all with `[p=<paintedtime> cl=<client ms>]`), `s_om_wavefile <path>`
(OpenAL Soft wave writer at rate R: the exact mix), `s_om_focusmute` (1 = silent while the window is inactive, as
Defsnd), `s_om_reverb` (0).

## Black-box method
- `test/run_session.ps1 -Backend defsnd|omsnd -Script <cfg> -Tag <name>`: runs the test copy on a separate,
  never shown desktop (no focus, no input from the owner), records **only the game's process tree** with
  `test/proccap.exe` (Windows process loopback, 48 kHz 16-bit stereo, gaps filled from packet time stamps).
- Defsnd's secondary buffer has no `DSBCAPS_GLOBALFOCUS`, so DirectSound mutes it while the game is not the
  foreground window: a first Defsnd run recorded pure silence. `test/dsfocus.c` is a `dsound.dll` proxy for the test
  copy only (`-DsFocus`) that adds `DSBCAPS_GLOBALFOCUS` to secondary buffers and logs the requests
  (`dsfocus.log`: Defsnd asks for flags 0x28 = LOCSOFTWARE|CTRLFREQUENCY, 65536 bytes, 22050 Hz 16-bit stereo).
- Parental locks: like I7, valid "off" words are written to `HKCU\Software\Raven Software\SoF` only while the game
  starts (`player/test/sof_locks.py unlock`) and the key is restored byte-identically from the I7 backup as soon as
  the test script runs (verified before and after every run).
- `test/soundfit.py <capture> <reference>`: finds each occurrence of a stock sound in a capture by normalised
  cross-correlation and fits its gain per side (gain 1 = the file's own sample values).

## Findings (black box)
1. Calibration (`exp_menu`, main menu, `play menu/First`, `play menu/Second`): Defsnd plays them at gain
   **0.4177 / 0.4166** both sides = 153 · trunc(0.7 · 256) / 65536 = 0.4179, i.e. a local sound in the menus is at
   volume 153, not 255. SPEC-040 1.1 lists "not active → 255" before the listener rule; the observed order is
   Quake II's (listener entity first). OMsnd 0.2 first had 255 (gain 0.695), now follows the observation. The
   recorder path is gain-exact (no level change through Windows' mixer/resampler at these levels).
2. `Cvar_Get` with three arguments (SPEC-AMEND-001 A) crashed SoF.exe (access violation right after
   `------- sound initialization -------`); with a fourth argument NULL (OMsnd 0.1 did that) it runs. The engine
   evidently reads a fourth argument (the change callback of the cvar object, SPEC-002 +0x10).

3. Sound-processing gain (scenario u1, network client, local sounds at volume 153, no music). Fitted gains (L = R):

8. `stopsound` (S_StopAllSounds → Quake II S_ClearBuffer) in m1: Defsnd's music has a silent gap of ~0.15–0.2 s
   (the mixed-ahead part of the DMA ring is zeroed) and then continues on its old timeline (same occurrence fits

   no gap but jumped 0.19 s ahead (a second occurrence 0.190 s later). Fixed: `Out_Clear` replaces the unplayed

9. Output latency (scenario t1, relay command `set s_testsound 1` → onset of the Quake II test tone in the capture,
   1 ms resolution): Defsnd 187/188 ms (on/off), OMsnd 0.2 237/238 ms. The extra 50 ms are OpenAL Soft's device
   buffering behind the source (its WASAPI path), which OMsnd's DMA clock did not count. Now the clock is
   frames played − device latency (AL_SOFT_source_latency). Music onsets in m1/u2 showed the same offset
   (first frame → music start: Defsnd 0.227/0.228 s, OMsnd 0.275/0.308 s). With the correction (t1_omsnd_v3):
   210/210 ms, device latency 705 frames (32 ms) reported; the remaining ~22 ms (about two frames) were left.

    capture came from OpenAL Soft's default resampler (m1 ran before the switch to the 47th-order sinc) and from
