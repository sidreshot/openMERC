# G10 — Game-module savegames (game/src/save/, g_save.cpp)

Implementation journal (C team). Specs: SPEC-752 (sequence, encodings, GAME/CLNT/LVLC/EDCT, script chunks via G6b),
SPEC-303 (container; engine side done by I1a), SPEC-013 (GHLI via G9), SPEC-700 (AI block via G2), SPEC-003 (`INVN`),
SPEC-006, SPEC-001 (exports 0x10–0x1C, 0x40/0x44; imports 85/86, 67); SPEC-781 (`PLNM`/`PLPI`/`PLWA`),
SPEC-791 (`OINM`/`EDOI`, G9).

## State (2026-10-25 13:30)
- Save and load of single-player games work in the original SoF.exe with OpenMerc's module (listen game and
  dedicated server): the save limit matches the original message for message, a loaded game continues like the
  uninterrupted one (see Results). Remaining differences come from AI helper entities (G2) and package state that is
  not saved yet (Needs).
- Blocked: "save after a level change" with OpenMerc's module — every single-player `gamemap` crashes in the first
  frame of the new level (player.dll under ClientBeginServerFrame → PlayerThinkInventory), also without any
  save; the kept inventory still uses Ghoul objects the level spawn destroyed (Needs from G18 (5)). The level-change
  automatic save itself is written and cross-loads.

## Design
- Level section in the original order: FTSZ, LVLC + STRG, NMED + EDNM/EDCT/STRG, scripts (G6b), AI block (G2 → G9,
  G3, G4), OINM (G9), PLNM/PLPI/PLWA; then OpenMerc's tail: `OMCN` + `OMCL` (client private part) per slot, `OMXN` +
  per extension `OMXI` + its chunks. Game section: GAME, per client CLNT [+ INVN by the player module].
- Record sizes are the original's (GAME 1688, CLNT 1536, LVLC 1440, EDCT 1124). EDCT is OpenMerc's edict image
  (prefix and string fields 420–500 at the original offsets); its last 48 bytes go into the world-link area, which
  is never saved (the entity is unlinked while written). Every pointer field is listed in `save_records.cpp`.
- Callbacks and pointers to static tables are image offsets (SPEC-752 2.1 permits own tables). FTSZ =
  {'OMG1', code CRC, image size, code size, sizeof edict/client/level, EDCT size, extensions}: a module with other
  code, or the original, refuses the level with `Function index tables have changed size` (seen in a test after a
  rebuild — a clean refusal instead of foreign offsets). Rebuilding unchanged code keeps saves valid.
- GAME: all SPEC-752 3.1 fields at their offsets; the open 92 bytes hold the difficulty record (measured, below).
  Mission statistics (0x618) stay 0: the module has no statistics yet (G18).
- CLNT: player state, ping, and the persistent fields at the original's offsets (userinfo 204, name 716, best
  weapon 736, fov 756 (int), connected 760 = 0x2F8, health 764, max health 768; inventory presence 844, second
  object 852 = 0). The rest of OpenMerc's client is OMCL.
- Read: FTSZ check; the spawned level's AI objects (G2 `LevelStart`), bodies (`Body_ReleaseAll`), Ghoul glue
  (`GG_FreeAll`) and the player module's cached in-view models are released; entities unlinked and cleared; LVLC,
  entities (each linked), scripts, AI, OINM, items, tail; clients re-attached, `pers.connected` = 0, Ghoul id
  remap, in-view models precached again. Level-tagged memory is *not* freed (deviation from SPEC-752 1.2: package
  tables of the spawn, e.g. G7's ambient sets and G4's roster records, stay valid; the spawn's strings leak until
  the next level).
- Save: entities are unlinked while written and linked afterwards — all of them, also never-linked ones: the
  original's saves do that (after a save their link bounds and engine values are those of linked entities).
- Save limit per level (black box, below): `level.g10_savesleft` (G10 block in level_locals_t), saved with LVLC.
- `set g10_savetest 1` before a `save`: after the real level chunks the level is written to memory, read back into
  the running game, written again and compared (`g10 savetest: ...` on the console). The level cannot continue
  after it (the read destroyed the Ghoul objects the clients' live inventories use): the inventories are detached
  and `killserver` is queued.

## Black-box findings (original 1.07f module, test copy `D:\Games\SoF-test-G10`)
- The original engine's `save` stops a dedicated server before it asks the game module (both modules, nothing in
  the log, no game frame on the stack): manual saves are made in listen games (`g10listen.py`), loads work on the
  dedicated server (`g10run.py --load`).
- GAME 0x63C–0x697 (automatic saves at skills 0, 1, 2, 4 decoded against SPEC-760 B9.2): 0x63C int 0;
  0x640–0x658 T-a…T-g; 0x65C encumbrance value (int); 0x660 S-a; 0x664 T-h; 0x668 cheats (int); 0x66C T-i (int);
  0x670–0x684 alert gain, alert fade, max-alert duration, spawn interval at max alert, max characters near, spawn
  interval; 0x688 saves allowed (= sk_saving); 0x68C S; 0x690 T; 0x694 difficulty score.
- Save limit: per level. GAME 0x688 stays at sk_saving; the original's LVLC 0x4EC holds the saves left (1, then 0
  at skill 3). Messages (singleplr): n ≥ 2 left SAVES_N_LEFT, 1 SAVES_ONE_LEFT, 0 SAVES_USED_UP, refused
  SAVES_NO_MORE; loading restores the level's count (save → load → save prints SAVES_USED_UP, svc_sp_print 0x0605
  in the 14th demo block in both modules).
- Loading: svc 29 + svc 30 (byte 0x1E then 640 bytes) go to the client before the first frame; the game is paused
  after a listen-game load (`set paused 0` continues).
- The original's own load is not byte-stable either: a save, load, save cycle changes AI ids and the order of the
  AI chunks, GHLI images, link bounds of entities that were never linked, Ghoul ids in `frame`.

## Results (2026-10-25, skill 2, fixedtime 25; data in `openmerc-data\g10\`)
- Cross-loading: a level section is refused by the other module with the original's game error `Function index
  tables have changed size` (both directions: `D_orig_loads_om`, `D_om_loads_orig`) — by design: OpenMerc's entity,
  client and level records are its own layouts (SPEC-760 1 / SPEC-780 1: private), its callbacks are image offsets
  (SPEC-752 2.1; the original's table order is SPEC-752 open question 1), and G3's body images are private
  (OPEN_QUESTIONS G3 22). Automatic saves (game section only: GAME, CLNT, INVN) load in both modules: the original's
  level-change `auto.sof` (tsr1 → tsr2) in OpenMerc and OpenMerc's in the original; the player state after the load
  depends only on the loading module (`D_auto_*`).
- Load in both modules, client capture (dedicated server, `capdiff.py`): tsr1 (`D_orig_own`/`D_om_own`) — configstring
  sets, baselines (except G7's monitor prop), last-frame entities, player state, message kinds, TE kinds, Ghoul strings
  equal; kos1 mid-combat (`D_orig_kos1`/`D_om_kos1`, 49 entities at equal numbers) — sets and baselines equal; combat
  intensity (TE 9 43/21, TE 6 7/1), stealth meter and music value differ (AI/G7, not the save).
- G3 hand bolt: loaded characters never fired (`fire ... -> 0` every think) because G3's body leaves the right-hand
  bolt id 0 after reading and `Fire` does not look it up; G10 calls the public `HandBolt(0)` after the load
  (workaround, Needs from G3). With it the kos1 shooter fires again after the load (`L_om_kos1_trace`).
- Chunk outline of a save: OpenMerc writes the original's sequence; differences in counts come from the game state
  (OpenMerc's AI/Ghoul objects differ) and the OM tail (`OMCN`, `OMCL`, `OMXN`); CVCN 46 vs 50 (G18 registers
  `sk_saving` and others without the save flags).
- Continuation (`cont.cfg`, tsr1; `cont_kos1.cfg`, kos1 mid-combat in god mode): save a, demo + 100 frames, save b;
  load a, demo + the same input, save c (b and c at the same level frame in both modules). tsr1 `savediff b c`:
  scripts, Ghoul records, attached objects, items identical; GHLI differ (new instance ids); AI chunks: AIBM 6, AIBE 1,
  AIAI 1, OMCL 1; entity records: link values of never-linked entities (fixed since: save links every entity), 16
  Ghoul ids in `frame` (the original: also 16), 7 entities at other numbers (G2 helpers, below). The original's own
  b-vs-c: AIAI 85, AIRD 82, AIBM 79, GGOB 117 … differ.
  kos1: 8 entity records differ (7 Ghoul ids, one corpse), AI chunks AINS 4, AIAI 3, AIBM 2; the original's own
  b-vs-c on kos1: 123 records, AIBM 66, AIAI 10, GGOB/GGOI/GGBI all. Demos (`demo2cap.py` + G6b's timeline): tsr1
  b-vs-c streams identical (0 diff lines); kos1: the shooter keeps firing after the load in both modules, shot
  timing differs in both (random spread, aim state).
- Self-test (`conttest.cfg`): image after write → read → write: equal chunk sequence; outside the AI block only OMCL
  differs (the `connected` flag the read clears, SPEC-752 1.2); AI chunks differ by their ids (counter, SPEC-700).
- Save limit (`savelimit.cfg`, skill 3): identical messages to the original, before and after a load (svc_sp_print
  0x0605 in the same demo block).

## Needs from other packages
- G18: (5) **single-player level change crashes** (see State): the inventory object is kept across `gamemap`
  while the level spawn destroys every Ghoul object (G9's GG_FreeAll) - the original moves the inventory through the
  persistence cvars (SPEC-780 24, SPEC-003 slots 65/64) or rebuilds the view weapon (export 11). (6) After loading an
  automatic save (inventory read from INVN, existing at ClientBegin) OpenMerc's player starts without a weapon
  (stats[6] 0, clip size 6), the original with weapon 8 and 8/24 rounds, whichever module wrote the save.
- G18: (1) item-list accessors `extern "C"` `int ItemList_Count(void)`, `edict_t *ItemList_Get(int)`,
  `void ItemList_Clear(void)`, `void ItemList_Add(edict_t *)` (g_items.cpp) — G10 links them by name with
  fallbacks; without them restored items are not in the list (RevealHiddenItems, listpickups miss them).
  (2) The cvars `sk_saving`, `sk_spawning`, `sk_toughness`, `sk_maxencum`, `cheats` … are saved by the original
  (flags 0x10, SPEC-303 vector 5): the original's save has 50 cvars, ours 46. (3) Mission statistics (GAME 0x618,
  8 counters + time; SPEC-752 3.1) are not kept by the module. (4) G10 added one line in `p_client.cpp` ClientBegin:
  the svc 30 byte before the player module's full state (the original sends `1d nn 1e` + 640 bytes; without it the
  client stopped with "Illegible server message").
- G3: after reading a body (SaveFields, g3_human.cpp) `boltHandR`/`boltHandL` stay 0 until `HandBolt` is called;
  `Fire` uses `boltHandR` directly, so a loaded character cannot fire. Look the bolts up in the read branch (then
  G10's workaround in save_level.cpp can go).
- G2: the AI helper entities (`Nug Buddy`, FL_AI_HELPER) are freed by `ReadLevelAI` and made again at the next
  think, at other entity numbers (tsr1: 7 helpers move from 20, 123 … to 174, 175 …); the original keeps every
  entity across a load. Keep them (their EDCT is restored) and re-link them to their AI object. The trigger_sound
  list of the character manager is cleared on load (ManagerReset) and not rebuilt.
- G4: the per-character roster record (`edict_t::roster`, `RgChar`) is not saved; G10 gives a restored character
  the record its slot got at the level spawn when the classname matches. A save (e.g. through `G10Extension`) is
  needed for characters made during play and for the random set choice.
- G7: `props::PropData` (per-entity table) is not saved; after a load a prop keeps the data of the level spawn, and
  `inst0`/`inst1` point at Ghoul instances the load destroyed (turrets, search lights). Save it through
  `G10Extension` or re-resolve the instances after the load.
- G6b: after `ScriptGlue_ReadLevel` the worldspawn runner reference is -1, so ClientBegin after a load does not use
  the restored runner (AMEND-005 G6b.1: it should, when the restored script is READY).
- G6b's `spproxy` keeps the module under test loaded when the engine unloads the proxy (no FreeLibrary at
  Shutdown): after a `load`/map restart the module runs Init with the previous instance's statics (G18's string
  package cache then pointed at freed memory: "string singleplr_… not found"). G10's proxy frees it.

## How to build / test
- Build: cmd.exe `set OM_BUILD_DIR=<repo>\build-G10-x86` then `game\build.cmd Release`;
  proxy: `game\src\save\test\build_g10proxy.cmd`.
- Listen game: `python game\src\save\test\g10listen.py --dll orig|om --script game\src\save\test\scripts\cont.cfg
  --tag NAME [--skill 3]` → `openmerc-data\g10\NAME\{sof.log, proxy.log, *.sof, demos}`. Scripts that `exec` another
  script need it in `D:\Games\SoF-test-G10\base\`.
- Dedicated load: `python game\src\save\test\g10run.py --dll orig|om --load FILE.sof --tag NAME --seconds 20`.
- Compare: `soflist.py --outline A.sof`, `soflist.py --diff --outline A.sof B.sof`, `savediff.py A.sof B.sof`.
- Ports: 29530 (server / listen game), 29531 (client).
