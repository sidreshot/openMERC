## How to build
- `game\build.cmd` (MSVC x86 + Ninja; `OM_BUILD_DIR` picks the build directory, default
  `build-game-x86-Release`; `OM_CMAKE_ARGS` is passed to CMake). Output `gamex86.dll` + `.map` + `.pdb`
  (map/PDB for `test/symbolize.py`), `g18probe.dll`.
- Test builds while a sibling package does not compile: `set OM_CMAKE_ARGS="-DOM_GAME_SKIP=roster;bots"` leaves
  those `src/<package>/` directories out and links `game/test/stubs/<package>.cpp` (no-op hooks; stubs exist for
  ai, bots, nav, props, roster, scriptglue). `-DOM_GAME_SKIP_PACKAGES=ON` skips every package (needs stubs for
  modes/ghoulglue/damage too — not written). Never ship such a DLL. Reset with `-DOM_GAME_SKIP=`.

## Known differences on dm/jpndm2 (orig vs om) and their reasons
1. Entity numbers: map entities start at maxclients + 17 in the original (4 → 21, 8 → 25, 16 → 33) and at
   maxclients + 9 in OpenMerc. 8 of the 9 are created by the original before the first map entity whatever the
   bot setting (body queue is 8 of the 16 constant ones); the 9th exists only while the bot system is
   initialised (`sv_globalrankings 0`; G5's Bot_WorldSpawn could create it). Spec gap: OPEN_QUESTIONS G18 25.
2. Configstring order (index differences): precache order across packages differs; sets are compared instead.
3. Material-flag string (configstring 16) position 10 and the material debris/footstep/landing sounds
   (Impact/Break/*, Impact/GlassBreak/*, Impact/Surfs/*, Player/Land/*, player/foot/*/*): SPEC-760 B1.5 leaves the
   surface-type table incomplete and the sound list open. Spec gap: OPEN_QUESTIONS G18 27.
4. Ghoul files only in the original: `Items/Pick-ups/Ammo_single/ammo_556`, `ammo_rocket`, `healthsm`, `healthbig`
   models (precached by the original in DM on a map without them; no spec rule — OPEN_QUESTIONS G18 28) and
   `G_GUTS_LRG` (gore model, G3/G9).
5. Sounds `Ambient/Gen/Electric/spark1/2.wav` (light fixtures, G7 props).
6. Ghoul instance numbers in entity `frame` / player-state view weapon: allocation order of Ghoul objects.

## Unspecified layouts measured with the black-box probe (OPEN_QUESTIONS G18 18–23)
Measured by loading `g18probe.dll` (our own code) into the original engine and watching what a client
receives: one 32-bit word set per frame (int 0x44332211 / float 1234.5), the word index encoded in the game
time the probe returns. No engine code was read.

Player state (200 bytes, client record offset 0):
| Off | Field | Off | Field |
|---|---|---|---|
| 0x00 | pm_type int | 0x6C | view-weapon Ghoul instance **pointer** (engine converts to the id) |
| 0x04 | origin short[3] | 0x70 | (view weapon type, not observable alone) |
| 0x0A | velocity short[3] | 0x74 | weapon counter A byte; 0x76 counter B short |
| 0x10 | pm_flags byte; 0x11 pm_time byte | 0x78 | weapon-state seq byte; 0x79 resync byte; 0x7A inhibit byte |
| 0x12 | gravity short | 0x7C, 0x80 | not sent (remote-view model id?) |
| 0x14 | delta_angles short[3] | 0x84 | blend float[4] |
| 0x1A | move-scale byte (0 = no horizontal movement) | 0x94 | fov float |
| 0x1C | viewangles vec3 | 0x98 | rdflags int |
| 0x28 | viewoffset vec3 | 0x9C | ambient-set short; 0x9E music byte |
| 0x34 | kick_angles vec3 | 0xA0 | not sent |
| 0x40 | weapon kick vec3 (only [0] sent) | 0xA4 | stats short[16] |
| 0x4C | remote camera origin vec3 (float, 1/8 units) | 0xC4 | dm rank byte, 0xC5 ranked count byte |
| 0x58 | remote camera angles vec3 | 0xC6 | spectated byte; 0xC7 cinematic freeze byte |
| 0x64 | remote view entity int; 0x68 remote view type int | | |
