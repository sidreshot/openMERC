## State (2026-10-22)

Implemented: the whole library behind `ghoul_api.h` — file parsing and decoding, text formats, game imports
#61–#66, the three system objects (49 methods), model objects (29), instances (55), player-model descriptions (19),
playback / pose evaluation / events / bolt-ons / traces / bounds, savegame images, network replication (server and
client, reliable and unreliable streams, delta bases, demo stream), drawing through the 52-entry GL table (textures,
materials, software and OpenGL lighting, world-light fading, model lights, billboards, blob and projected shadows,

## Build / test

- Part of the engine: `engine/CMakeLists.txt` has `add_subdirectory(src/ghoul)`; targets `omghoul` (static library)
  and `omghoul_test` (option `OMGHOUL_TESTS`, default ON). In a full engine tree: `cmake --build <dir> --target omghoul omghoul_test`.
- Standalone (fast): after `vcvarsall.bat x86`:
  `cmake -S engine\src\ghoul -B build-I3-ghoul-x86 -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build build-I3-ghoul-x86`
- Run: `omghoul_test.exe [data root] [output dir] [--quick]`; data root default
  `<openmerc-data>\ghoul` (holding `pak0/ pak2/ pak3/` from `tools/pak.py x`), output default
  `<data root>\..\renders\ghoul-i3`. Without data the file/render parts print SKIP.

## For consumers (I1b, I2c, I4b, I7)

- Engine: fill `om_ghoul_host_t` (load by game path, print, fatal) and call `OMGhoul_Init`; game import #60 =
  `OMGhoul_GetSystem(OM_GHOUL_SERVER)`, #61–#66 = the `OMGhoul_*` functions; `gserver` = `OMGhoul_Command`.
- Network: per client frame call system 21, instance 52 per entity (returns the handle for the entity state), 18,
  20; acknowledge with 19; reliable data with 16/17 (payload of svc 26) — the engine adds svc byte and length.
  Client: 24 per svc 26 payload, 23 when loading finished, 25 per svc 27 with the svc_frame number and time.
- Renderer: system 38, 39, 37, 1, 2 at start-up; 36/34/35 per map; 28–31 per frame; derive the render-parameter
  block from `GhoulRenderParams` (it is the render-cull object). The GL table is immediate mode: a GL 3 core
  renderer has to emulate it (see `tests/soft_gl.cpp` for a complete emulation incl. matrix stacks).
- Stock character and first-person models face −Y in model space (OPEN_QUESTIONS I3-14).

## Not done / limits

- Hardware-lighting draw path (`ghl_light_method` > 2.5, GL lights) is implemented but only exercised through the
  software GL table, which ignores GL lighting; it has not been seen on a real GL context. The same holds for the
  texture-matrix (animated UV) and sphere-map paths (no image check).
- Light kinds 1–4: parsed since SPEC-AMEND-005 I3.10 (extra tracks read, meanings unknown; such a light acts like
  kind 0).
- System method 11 (full-path callback) is stored but files are read through the host's `load_file`.
- The older geometry layout (first word ≠ −1) is parsed as described but untested (no stock file).
- Spec gaps and chosen interpretations: `docs/specs/OPEN_QUESTIONS.md`, section "I3".
- Not run inside an engine yet (needs I1b/I4b to host the library). The network coding is checked against
  captures of the original; drawing only against the software GL table; the unreliable writer is checked by
  round trip (its time fields cannot be re-encoded bit-exactly from decoded values).

## SPEC-AMEND-005 (2026-10-25, applied by F5) — behaviour changes for I1c / I4c / I7 / I1b

Public interface unchanged (`ghoul_api.h`, `ghoul_host.h`); internal `Inst::net` changed (see I3.1). Tests:
`omghoul_test` 1243 checks, 0 failed (new: `TestAmend005`, `TestDeltaBases`).

| Item | Change |
|---|---|
| I3.1 delta bases | the acknowledged frame is per **instance and client**; a frame remembers the instances whose records were written and fitted the budget; acknowledging frame F moves only those instances to F; the base is the state stored for exactly that frame (else the baseline); states are stored per instance (≤ 20, shared by clients) at write time, also when the budget then drops the record; an unchanged instance stores nothing. A server that acknowledged a frame without an instance's record (lost frame + budget) keeps coding against the older acknowledged frame instead of a state the client never got |
| I3.2 paused raw phase | a paused instance's raw phase is evaluated at time A (not equal to A); Resume sets cursor time/phase to r(t) — the first method 45 after Pause delivers up to the pause point only, nothing is delivered twice after Resume |
| I3.3 repeated calls | method 4 with on ≠ 0 restarts event processing on every call (also when already on: skips keys, moves a paused pose, replaces a mode-3 fraction); a second Pause moves the frozen point |
| I3.6 Clone | copies the instance state + D, F, N only; user value, callbacks, note/matrix processing, cursor are new |
| I3.7 specular (software) | specular colour white when slot 1 has a texture, × render-parameter fog visibility; the specular pass restores blend off, (SRC_ALPHA, ONE_MINUS_SRC_ALPHA), offset off, depth writes on (the hardware two-pass and the 0.051 test came from I1c / AMEND-006) |
| I3.8 projected shadows | new mask basis (axis origin − light point, X/Y from the longest cross product), orthographic projection (not onto the ground), blur inside the touched rectangle, quad over the rectangle grown by 1 texel with the g = 16 × trace-fraction growth and the second-pair quirk, shifted by (origin − light point).xy (+ the directional vector when shadow-only), three passes offset by ±1 world unit at darkness × 0.3333; darkness × (tint alpha)²; mode 1 (blob) uses the same corners |
| I3.9 light activity | already done by I1c (part shown + visibility track) |
| hardware lights (F5, black box) | with `ghl_light_method` > 2.5 an OpenGL world/dynamic light's DIFFUSE and SPECULAR are its colour × (1 − `LIGHT_AMBIENT`) (0.4 by default): the original's Ghoul GL-table trace of `orig1.dm2` shows 0.4 × colour at every moment from 20 to 33 s, 0.2 × after `gserver LIGHT_AMBIENT 0.8`, 0.8 × after 0.2. Model omni lights unchanged (not observed). The SMG view-weapon pairs with the original's driver lighting went from 11.9 / 9.8 to 3.9 / 1.3 (weapon box, frames 253 / 298) |
| I3.10 LIGHT kinds 1–4 | parsed (extra tracks skipped) |
| I3.4, I3.5, I3.11–I3.15 | matched; I3.11 and I3.12 now covered by test vectors |
