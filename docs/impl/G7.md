# G7 — props and server effects

Implementation journal (C team). Specs: SPEC-770 (props, 194 classnames), SPEC-771 (server effects, `environ_*`, ambient
sets, music, effect emission rules); helpers from SPEC-791 (Ghoul glue, owned by G9), SPEC-760/761 (G18),
SPEC-720 (G3), SPEC-782 (G18).

## Layout
- `game/src/effects/` — SPEC-771
  - `fx.h` — **public** emission interface (namespace `fx`): temp entities with the SPEC-771 §C rules (debris and
    weapon-impact rate limits, lock_blood), impact descriptors, named effects with pending extension values, effect
    slots, rotation record, fade, entity events, one camera-shake tick, AI-noise hook. Other packages (G18
    projectiles, G3 gore, G4 vehicles) should send these messages through it.
  - `fx_emit.cpp` — implementation of `fx.h`.
  - `environ.cpp` — the 26 `environ_*` classes (§A).
  - `ambient.h` / `ambient.cpp` — `sound/sound.ams` loading, the three group lookups (also the mover lookup of
    SPEC-760 B5.1 for G18), `func_ambientset`, `environ_soundgen`, `func_musicControl`, the music rules (§B).
- `game/src/props/` — SPEC-770
  - `props.h` — **public** interface: spawn dispatch hooks, model tables, standard setup/break/explosion for other
    packages (G4 vehicles use tables 10–12 of the same format).
  - `prop_ghoul.h/.cpp` — thin layer over G9's glue (`ghoulglue/gg_ghoul.h`): model records, instances, bolt-ons,
    attached-object records (tracked parts, shown bits, link chain) and savegames are G9's; G7 adds bolt positions in
    world space, bolt-on transforms, the aim calls and note callbacks (registered once with `GG_RegisterCallback`
    in a fixed order: banner, valve, hanging meat, lamp_hang).
  - `test/g7test.py` — black-box runner/comparator (see "Tests").
  - `prop_tables.cpp` (Appendix A), `prop_core.cpp` (§2–§5), `prop_generic1.cpp` (§6A), `prop_turret.cpp`
    (§6A.7), `prop_generic2.cpp` (§6B), `prop_train.cpp` (§6B.9), `prop_level1.cpp` (§7A), `prop_level2.cpp`
    (§7B), `prop_lights.cpp` (§8), `prop_spawn.cpp` (classname table, hooks).
  - `props_save.h` / `prop_save.cpp` — **public** savegame support (G10): the per-prop table as the G10 extension
    record `G7PD` (see below).

## Hooks in G18's files

  `misc_exploding_heli` → marker, which matches SPEC-770 §9, and `target_temp_entity`).
- `g_spawn.cpp` SpawnEntities: one call `G7_LevelSpawned()` after loading progress 0.28 ("ambient sound init",
  SPEC-760 B1.3 step 5).

## Savegames (G10's request, 2026-10-25)
- Problem (docs/impl/G10.md): `props::PropData` was not saved; after a load a prop kept the data of the level spawn,
  and `inst0`/`inst1` (turrets, searchlights) pointed at Ghoul instances the load had destroyed.
- `props_save.h` / `prop_save.cpp`: `props::WriteLevelProps` / `ReadLevelProps`, registered as G10 extension
  `G7PD` (G10 calls them through its extension list, after entities, AI block and G9's attached-object records are
  restored). Chunks: `G7PN` (count) and one `G7PD` per entity with non-empty prop data. Static tables and callbacks
  through `G10_EncodePtr`, entities through `G10_EncodeEnt`, `inst0`/`inst1` as the index of the entity's tracked
  bolt-on part (0 none, -1 the entity's own instance) and resolved again from the restored tracked parts. The read
  clears the whole table first, so no data (or instance pointer) of the spawned level survives a load.
- Tests (G10's runners through wrappers on G7's copy SoF-test-G7b, ports 29482/29483, own hidden desktop
  `OMTestG7`: `openmerc-data/g7/g7listen.py`, `g7save.py`; scripts `openmerc-data/g7/savescripts/`). The engine's
  `save` stops a dedicated server with either module (also the original's), so saves come from listen games.
  - In-memory round trip (`g10_savetest 1`): ger2 (4 automatic guns, 223 prop records) and irq2b (2 big guns,
    2 searchlights): every G7 chunk equal after write → read → write (the differences reported are G2's AI block
    and one OMCL); the instance references resolve to the same tracked parts after the read.
  - Save, load, run 10 s, save again on ger2 and irq2b: no crash, both saves written.

## Tests
- `python game/src/props/test/g7test.py run --dll orig|om|<path> --map <m> --tag <t> [--sp] [--script ...]
  [--set "cvar value"]`: G18's harness on a G7 test copy (paks hard-linked, oracle untouched): `D:\Games\SoF-test-G7`
  or, with `G7_TEST=D:\Games\SoF-test-G7b`, the second copy (two runs in parallel; one loaded gamex86.dll per copy).
  `--sp` = single player through G6b's proxy (SP maps overflow the sound list as a DM server). Output
  `openmerc-data/g7/<tag>/`.
  - Ports (brief "Network ports", 2026-10-25): always G7's range 29480-29489 — copy G7: server `+set port 29480`,
    test client bound to 29481 (`g7client.py` wraps G18's sofclient.py), server `+set clientport 29484`; copy G7b:
    29482 / 29483 / 29485; a second client 29486/29487. A `--port` argument is ignored. A run is discarded
    (capture renamed `cap.invalid.jsonl`, exit 3) when the client received packets from another address, saw more
    than one serverdata or client_connect, or the server could not bind. SoF.exe command lines are checked
    against the 50-word crash limit.
  - Developer (brief, corrected 2026-10-25): the original dedicated server needs `set developer 1` inside an exec'd
    cfg — runtest's `+exec g18dev.cfg`; with developer 0 it never spawns the map, `+set developer 1` on the command
    line opens the modal "Developer Mode" box (SPEC-301 B1 step 7). g7test.py drops any command-line developer
    setting and adds `+exec g7dev.cfg` (developer 1) if no dev cfg is exec'd.
  - The runs quoted in this journal (before the rule) used server ports 27977-28033 and an ephemeral client port;
    `check_run` over all 164 captures of 2026-10-25 found no second serverdata and no second client_connect (the
    old captures do not record the sender address, so that is the only check possible for them).
- `g7test.py cmp <tagA> <tagB> --bsp <map.bsp>`: configstring sets (models/sounds/effects by name, so registration
  order differences of other packages do not hide G7 differences), baselines and every entity state seen in the
  frames matched by origin (sound/model/effect-slot indices resolved to names), temp entities, effects, sounds.
- `g7test.py mkmap <src.bsp> <name> [--keep-spawn x,y,z] [--add 'k=v;...']`: test maps with extra entities written
  to the test copies' `base/maps/` (game data stays out of the repository).
- Helpers in `openmerc-data/g7/` (data, not repository): `batch.sh` (DM maps), `spbatch.sh` (SP maps), `events.py`
  (event timeline of a run), `kinds.py` (event counts A vs B), `evcmp.py`, `track.py` (state changes near a point),
  `mkshot.py` (g7shot map + script), `amsdump.py` (sound.ams sets), `ams/` (extracted sound.ams).
- dm/raven spawn (640, −672, 24) faces yaw 90: script `yaw`/`pitch` values are relative to it (yaw 0 = north);
  the shot start is origin z + 35.
