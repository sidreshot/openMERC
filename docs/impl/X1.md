### Run
```
D:\Games\SoF-open-X1\openMerc.exe -portable -basedir D:/Games/SoF-open-X1 +set user <home dir>
    [+set snd_dll OMsnd.dll] [+set vid_fullscreen 0 +set r_mode 4] [+map tsr1]
D:\Games\SoF-open-X1\openMerc-ded.exe -portable -basedir D:/Games/SoF-open-X1 +set user <home dir> +exec server.cfg
```
`-portable` + `+set user` keep everything (config, saves, logs) in the home directory. Settings needed before the
client starts (`snd_dll`, video) can also go into `<home>\config.cfg`, which the engine runs before the client
initialises. **Single player / listen server needs valid parental-lock words** (finding X1-1).

## Findings
(owner by the journals; each with the smallest reproduction)

X1-1. **The open stack refuses its own single-player client on this PC** (and on any PC whose lock store is
missing or invalid). Repro: `xrun.ps1 -Map kos1 -Tag smoke_kos1` without `-Unlock`: `[0.0.0.0]:0:
rejected_violence` / `Server violence settings are incompatible.` 3355 times in 120 s, no level. Cause: the engine
forces every lock when the store is invalid or absent (`sof_locks.c`, SPEC-313: `cl_violence` 63) and GS.15
(SPEC-AMEND-005, `SV_SetPureViolenceBit`, `sv_init.c`) sets the pure bit only for the stock module checksums, so
`sv_violence` is 31 with our modules and the check `(sv & cl) == cl` fails. With the original modules on the same
engine the pure bit is set (63) and the client joins — I1b's campaign runs never hit it. Faithful to the original
(the original SoF.exe refuses a non-stock listen game the same way), but it makes the fully open stack unplayable out
of the box. Owner: I1b (GS.15) / I1a (lock store) — a DEVIATIONS decision for the coordinator (e.g. treat a missing
store as unlocked, or count OpenMerc's own module pair as pure). Not changed by X1.
